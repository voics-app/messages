# Scheduled messages implementation status

This branch implements the backend of messages#61 in reviewable checkpoints. The interface design is in [docs#182](https://github.com/voics-app/docs/pull/182), ADR0028 and merged [contracts#50](https://github.com/voics-app/contracts/pull/50). The feature remains disabled by default and has not been deployed.

The domain owns request identity, time/text rules, revision-fenced transitions, preparation recovery, dependency backoff and delivery outcomes. The application owns create/replay, edit/cancel, ownership, discovery ports and a single claimed dispatch attempt. `CreateMessage` supplies ordinary composition and publication with fresh authorization around the claim. The real HTTP access adapter bypasses both cached values and older in-flight requests for refresh.

The Scylla adapter now commits the job, author/channel quota and active discovery in one author-partition SERIAL/QUORUM conditional batch. It creates a distinct vnode companion keyspace on the existing cluster, checks replication against the main keyspace and retains the original session binding. The due index has 64 shards, bounded 100-row pages and persistent cursors. Real Scylla tests exercise competing repositories, quota release/replay, cancel/claim/recovery and cursor rewind. The dedicated scheduled message writer disables opaque driver retries for insertion.

The worker rotates four shard pages per scan, buffers at most 400 unique keys, permits four dispatches in flight and immediately refills completed slots. Persisted cursors resume/wrap, a full buffer does not advance past an unretained candidate, and shutdown drops unclaimed buffered work. Real Scylla journal/message tests cover competing workers, lost claim/write results, deletion/restart without resend, post-claim revocation and preparation-abort fencing. The 24-hour overdue cutoff takes precedence over dependency backoff.

All five routes are now wired to the application service, with canonical generated DTOs and explicit validation for constraints the generator cannot encode. Eight HTTP tests cover privacy/authentication, disabled/private modes, replay/edit/cancel, membership loss, validation, all six visible states, timezone normalization, cursor/retention and rate limits. Captured responses from all six states pass the canonical AJV validator; twelve missing-field or wrong-state counterexamples fail. An enabled server starts the worker, includes its liveness and tables in readiness, polls once per second, and drains claimed work for at most 30 seconds at shutdown. Configuration tests cover the default-off flag and companion identifier validation.

The production Scheduler lifecycle is now exercised over TCP HTTP with real Scylla and two workers. The author client can disconnect, no send occurs early, one delivered message is visible through the second fixture principal's history, cancellation prevents delivery, and readiness becomes unhealthy after shutdown. A real one-second-paced 225-job hot-shard test reads pages of 100/100/25 with four in flight and releases all quota. Journal metrics include recovery to unknown and claim-to-outcome time; scan metrics expose observed claim age and freshness. See the operations document for exact fixture boundaries and nominal 16-second shard rotation, not a five-second delivery promise.

Author inspection now also reconciles expired unindexed preparation, clearing content and releasing quota without send permission. A genuine RED previously returned an empty list indefinitely until the next create; bounded get/list/cancel reconciliation fixes that gap. Unaccepted reservations without any later author operation still require that operation for discovery; there is no global author-table scan.

Remaining acceptance is independent backend review, compatible client surfaces, real two-account/API/gateway/client end-to-end delivery and rollout-specific alert configuration. Client work is coordinated in a separate branch. This is not a completed issue 61.

The intended storage guarantee is one insertion attempt after a durable claim. Lost acknowledgements or abandoned claims become visible `delivery_unknown`, without automatic resending. An original attempt may later certify storage. Publication and accounting remain best effort, as with ordinary messages. Current author account eligibility additionally requires [api#150](https://github.com/voics-app/api/pull/150).
